## User Stories

### US-1
- As a Raspberry Pi operator/admin., I want present critical monitoring status clearly at first glance and keep live dashboard updates reliable with explicit degraded-state signaling, so that the workflow remains reliable and traceable.
- Trace: FR-1, AC-1
- Acceptance Criteria:
  - Given an authenticated operator on Dashboard, when live telemetry is healthy, then critical status is visible in first viewport and corrective navigation is reachable in two clicks or fewer.

### US-2
- As a Raspberry Pi operator/admin., I want preserve strict security boundaries: authenticated access, CSRF/origin protection for state-changing routes, and no privileged execution from web handlers, so that raspberry pi operator/admin.s can access the right capabilities safely.
- Trace: FR-2, AC-2
- Acceptance Criteria:
  - Given a state-changing endpoint request, when auth session is invalid or CSRF/origin validation fails, then the request is rejected and an auditable security event is logged.
